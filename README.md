# 灰烬渡口

安装：`npm ci`

本地启动：`npm run dev`，打开终端显示的地址。

类型检查：`npm run typecheck`
逻辑测试：`npm test`（任务结算的 16 项场景验证）
生产构建：`npm run build`

Docker 启动：`docker compose up --build`，访问 http://localhost:18071。

## 任务系统

部署阶段（尚未产生任何行动记录）可在左侧「任务配置」面板选择四类任务，
并在地图上直接绘制目标区域：

- **歼灭任务**：消灭敌方所有角色获胜（默认，旧战斗自动沿用）。
- **护送任务**：选择一名苍蓝军单位作为护送目标，绘制出口区域；目标在一次
  行动完整结算（含灼烧等持续伤害）后仍存活并位于出口即成功，目标被击倒即失败。
- **占点任务**：绘制目标区域并设定连续占点回合数；每个新回合开始时若区域内
  有苍蓝军存活单位则累计，中断则清零，达到要求回合数获胜。
- **限回合生存**：设定回合上限，苍蓝军在完整结算中撑到该回合即成功。

### 结算与持久化

- 移动落点、技能结算、结束行动（回合推进）三条路径都调用同一个
  `settleMission`，任务进度与胜负原因（`endReason`）写入战斗快照并随每个
  行动事件保存，回放跳到任一步都能看到当时的目标区域、进度与胜负原因。
- 失败条件与成功条件同时成立时优先失败（如护送目标同一步抵达出口又被灼烧击倒）。
- 任务配置在应用前经过 `validateMission` 校验；损坏配置由 `normalizeMission`
  归一化为歼灭任务。加载旧存档时仅在内存中补齐字段，不回写覆盖原存档；
  保存前校验失败会抛出错误并保留原有存档。
